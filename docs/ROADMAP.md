# 路线图与协作分工

## 角色

- 轻薄本开发者：项目文档、数据治理、接口设计、数据检查、轻量测试、代码评审和 Git 集成。
- 台式机伙伴：硬件确认、经批准后的数据准备、基线训练、联邦实验运行、性能记录和可复现实验环境说明。

## 阶段 0 项目治理与协作

交付物：架构文档、数据治理记录、任务分工、Git 协作约定、SSH 推送流程。

当前结果：已建立 GitHub SSH 协作、代码仓库、忽略规则和伙伴交接文档。

验收：不含原始数据、密钥、.venv、模型权重或训练输出；双方可克隆仓库。

## 阶段 1 非训练数据准备 已完成本机部分

交付物：任务配置、数据接口、标注检查、样本清单、驾驶员级划分、联邦客户端规划、训练前条件检查和自动测试。

当前结果：pilot 数据的本地检查流程完成；当前数据只有 1 个驾驶员组，因此工具明确阻止正式训练。

验收：无需 GPU 即可运行静态检查与单元测试；当前 36 项测试通过。

## 阶段 2 单机基线

前置条件：数据许可确认、至少 3 个驾驶员组、可用训练硬件、依赖版本确认。

交付物：数据卡、训练配置、单机基线指标、失败案例记录。

验收：伙伴台式机可从干净环境复现实验，并保留数据版本、随机种子、划分和硬件记录。

## 阶段 3 联邦学习模拟

前置条件：阶段 2 的单机基线稳定，且训练划分至少保留 2 个不同驾驶员训练组作为客户端。

交付物：多客户端划分策略、聚合器、通信与隐私评估、实验报告。

验收：与单节点基线比较，并记录精度、延迟、资源占用和隐私风险。

## 阶段 4 部署评估

交付物：推理接口、模型版本管理、监控、告警边界、安全与隐私评审材料。

验收：仅在授权和评审通过的受控环境中开展演示。

## Git 工作约定

1. 在 Ubuntu 中编辑、测试、`git add`、`git commit` 和 `git push`。
2. 每次开始工作前执行 `git pull origin main`，完成一组测试通过的修改后再提交。
3. 不把数据、权重、.venv、Token 或 .env 提交到仓库。
4. 当两人同时改动同一文件时，先拉取、检查差异并协商解决；不要强制覆盖远程提交。
