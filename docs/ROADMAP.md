# 路线图与协作分工

## 角色
- 轻薄本开发者：项目文档、数据治理、接口设计、轻量测试、代码评审和 Git 集成。
- 台式机伙伴：经批准后的数据准备、基线训练、联邦实验运行、性能记录和可复现实验环境说明。

## 阶段 0：项目治理与设计
交付物：架构文档、数据治理记录、任务分工、Git 协作约定。
验收：不含原始数据、密钥、.venv、模型权重或训练输出；双方可克隆仓库。

## 阶段 1：可复现的非训练骨架
交付物：配置模式、数据接口、模型接口、聚合接口、日志和测试框架。
验收：无需 DMD 和 GPU，即可运行静态检查与最小单元测试。

## 阶段 2：单节点基线
前置条件：数据许可确认。
交付物：数据卡、训练配置、基线指标、失败案例记录。
验收：伙伴的台式机可从干净环境复现实验。

## 阶段 3：联邦学习模拟
交付物：多客户端划分策略、聚合器、通信/隐私评估和实验报告。
验收：与单节点基线对比，并记录精度、延迟、资源占用和隐私风险。

## 阶段 4：部署评估
交付物：推理接口、模型版本管理、监控、告警边界、安全与隐私评审材料。
验收：仅在授权和评审通过的受控环境中开展演示。

## Git 工作约定
1. 在 Ubuntu 中编辑、测试、git add 和 git commit。
2. 通过 Windows Git 推送 WSL 项目，避免 WSL 代理转发不稳定。
3. 每项工作使用独立分支；合并前由另一人审阅。
4. 不把数据、权重、.venv、token 或 .env 提交到仓库。
