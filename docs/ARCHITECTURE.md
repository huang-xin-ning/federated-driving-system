# 系统架构 第一阶段

## 目标

构建面向智能网联汽车的驾驶员行为监测研究原型。未来的车辆或边缘节点保留本地视频与特征，只交换受控的模型更新；服务端验证和聚合更新后分发全局模型。

当前实现聚焦于数据与实验前的防错流程，尚未实现模型训练、参数聚合、加密传输或推理服务。

## 当前状态与边界

- 本机已经下载 DMD pilot 压缩包和标注元数据，并完成只读检查。
- 数据授权、训练允许范围、团队共享范围、公开展示和商业使用范围仍未确认。
- 当前 pilot 只有 1 个驾驶员组，不满足按驾驶员划分训练、验证和测试所需的至少 3 个组。
- 本机脚本可检查标注、构建本地样本清单、探测视频帧边界、规划分组和模拟联邦客户端；这些脚本不会训练模型。
- 原始视频、可识别图像、凭据、模型权重和训练输出不进入 Git。

## 已实现的逻辑组件

1. 数据检查：解析 OpenLABEL 标注，检查 DMD 压缩包元数据、标签映射和驾驶员组。
2. 清单管线：计划候选帧、构建本地候选清单、使用 ffprobe 过滤缺失视频与越界帧。
3. 实验门槛：要求足够驾驶员组和目标标签，避免将单驾驶员数据当作正式训练集。
4. 划分规划：按驾驶员生成互不重叠的训练、验证和测试组，并只在通过覆盖检查后写出本地 CSV。
5. 联邦规划：将训练驾驶员组映射为模拟客户端，并要求至少 2 个训练客户端。
6. 轮次元数据验证：对未来模型更新检查模型版本、客户端唯一性和样本数；不读取权重。

## 未来联邦学习流程

1. 服务端发布已经批准的全局模型版本。
2. 每个客户端只使用本地授权样本完成有限轮训练。
3. 客户端仅提交经过保护的模型更新和必要的聚合统计信息。
4. 服务端验证更新元数据、执行聚合、评估并登记版本。
5. 只有通过质量与隐私检查的模型才能进入受控推理测试。

## 隐私与安全基线

- 原始数据始终保留在数据节点，不进入代码仓库或聚合服务。
- 后续才会设计和验证安全聚合、更新裁剪、差分隐私及成员推断防护；当前不宣称已实现。
- 密钥、令牌、环境变量文件和本地路径必须被 Git 忽略。
- 实际部署只能在数据授权、个人信息保护评估和安全评审完成后进行。
