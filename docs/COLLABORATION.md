# 双人协作与交接

## 文件共享

代码和文档通过私有 Git 仓库协作。双方分别创建 `.venv`。数据、模型权重和训练输出放在经双方约定且访问受控的存储中，不直接推送 Git。数据共享必须符合数据方授权，私有仓库并不替代授权。

## 日常工作

1. 开始前检查 `git status`，确认自己有无未提交修改。
2. 在工作区干净或已有改动妥善保存后同步远程；不以 reset 或强制推送解决不明冲突。
3. 为各自任务使用独立分支，避免同时修改相同文件。
4. 本地验证后检查差异，提交明确范围的代码。
5. 推送分支并创建 Pull Request，由另一人查看后合并。

尚未配置远程和认证时，先完成仓库初始化与访问验证。不要在 URL 中嵌入密码或令牌。推送前执行 `git diff --cached --stat` 和 `git diff --cached`，确认没有环境目录、数据或秘密。

## 路径配置

复制 `configs/paths.example.json` 为 `configs/paths.local.json` 后填入各自路径。所有示例路径都是占位值，目前尚未实现配置加载功能。后续代码应通过参数或配置加载本地路径，禁止硬编码他人的用户名与数据盘路径。

## 结果边界

CPU 小样本测试验证流程能运行，不能替代模型效果评估。模拟联邦实验不能直接宣称完成实车部署。隐私结论必须对应明确威胁模型、机制和实验依据。
